# One SQLite file: prefixed source tables under a shared record and link index

The reference database is one SQLite file with two layers. The source layer keeps imported data under upstream names, with one prefix per source (`dbc_`, `world_`, `lua_`, `offsets_`, `ui_`). The unprefixed index layer (`record`, `link`, the FTS tables, `enum_value`, `enum_field`, `meta`, `source`) points at source rows, so the generic search, get and related tools never need to know about individual kinds. We rejected ATTACHing one file per source, which gives cleaner schema-qualified names but means more downloads and a more complex open step. We also rejected per-kind tables, which would need a UNION for every cross-domain search. Native addresses from the client's registration tables are data on the Lua API record, not Links; a Link to Offsets exists only where a curated Offset entry has the same address. Raw SQL makes every table and column name public, so a rename or drop is a schema-major change, and the pipeline enforces this by diffing against the previous release.
